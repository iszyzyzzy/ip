# LP-11、背光包发送阶段与实际回读

本记录更新此前“主机先初始化就能保证 LP-11”的不完整表述，保留失败和成功的实机对照。
分支：`codex/fl7707-lp11-rx`。仅 CAM/DISP0 运行时加载，启动配置未改动。

## 关键修正及结果

prepare_prev_first 只改变 panel/bridge 的调用顺序，不配置时钟线模式。
RP1 源码根据 MIPI_DSI_CLOCK_NON_CONTINUOUS 决定 LPCLK_CTRL 是 1 还是 3。
加入该 flag 后 flags 从 0x805 变成 0xc05。

| 项目 | 原状态 | 非连续时钟修正后 |
| --- | --- | --- |
| LPCLK_CTRL | 1 | 3 |
| PHY_STATUS（复位释放前后） | 早先运行时采样 1529 | 15bd |
| CLK Stop 位 bit2 | 早先采样为 0 | 复位前后为 1 |
| 初始化前 0A | -5，无有效数据 | ret=1，08 |
| 初始化后 04 | -5，无有效数据 | ret=3，93 65 04 |
| 初始化后 0A | -5，无有效数据 | ret=1，18 |
| ERR0/ERR1 | 首次采样 0/2 | 各次成功读取阶段均 0/0 |

旧 PHY_STATUS 采样发生在视频运行时，不能单凭它重建旧版本整个复位期间的状态；
新版本已在 prepare 中分别采样复位前、释放后及各读请求后。

DSI INT_ST1 bit1 的 LP 接收超时含义用同类 Synopsys 控制器的 ST 官方 CMSIS 定义交叉核对。
实际成功回读表明，不必补主机接收寄存器也能建立基本通信；这不等于所有主机配置在所有面板上都最优。

## 对接收配置审查意见的验证

实机控制器 VERSION=3133312a（Synopsys 1.31），修正时钟后仍保持：

- PCKHDL_CFG=5，BTA 与 EoTp TX 开启，RX ECC/CRC 未额外启用。
- PHY_TMR_RD_CFG=0。
- PHY_IF_CFG=1，2 lanes，STOP_WAIT 字段未额外写入。

以上状态下 0A、04 等已正常应答。因此本次未启用 MAX_RD_TIME=10000、接收 ECC/CRC、
STOP_WAIT=0x20 的补丁，也没有保留该试验补丁的写寄存器路径。
先前“BTA 已开启”不足以排除时钟配置问题，之前的通信失败并非已经证明的屏幕硬件故障。

## 背光命令发送阶段及亮度顺序

上版 enable 重发 C7 扩展长包会占用视频模式的 LP 命令窗口，且发生在厂家 EF 之后。
现改为 C7.PWM_OE 在原表对应位置打开，仍在 Command Mode 中；
视频阶段只用 53 的短包开关背光，不再重发 C7。

另外，亮度写入顺序存在实测差异：

| 顺序 | 54 控制回读 | 52 亮度回读 |
| --- | --- | --- |
| BCTRL 复位关闭时写 51，然后才 53=24 | 24 | 00 00 |
| 先 53=20，写 51，再在视频稳定后 53=24 | 24 | 80 00 |

先用 53=20 允许亮度控制、保持 BL 关闭，视频启动 50 ms 后再置 BL=1。
51 的单参数和双参数都做了相同顺序下的对照：均读到 80 00，不能声称单参数写法是本次点亮修复。
默认仍采用厂家手册画出的双参数；可用 brightness_bytes=1/2 重复该对照。
52 请求两字节时 RP1 返回的是 FIFO 读取长度，不能仅凭第二字节为零推断面板物理响应包有两字节。

## 黑屏仍存在时的证据

用户确认通信恢复后仍无画面、背光。

- 0A=18，按所供 FL7707N 手册解释为 Sleep Out/Normal，但 Display On 与 Booster 状态位仍为 0。
- 54=24、52=80 00，已有标准控制及亮度命令写入的证据。
- 在原表 BA/C7 写入后立即读：BA 写首参31、读00；C7 写首参90、读00。
  在 EF 之后再读 C7 也为00。扩展寄存器 DCS/Generic 读取都试过，但零值本身不能证明它们一定可按此方式回读。
- 0C 读到70，与 FL7707N 文档的 RGB888 默认值相符。
- DA/DB/DC 分别读93/65/04，与04结果一致。这个 ID 也见于 JD9365 系列实测记录，
  但 ID 可由模组定义，且0C行为与所供资料相符，不能仅凭 ID 就换另一套屏幕的电源/GIP参数。

曾在无其他发送进程时，用已确认地址 1f0011c000 的 /dev/mem 映射发送同一 B9 解锁值的
Generic 长包作窄范围对照；视频模式下出现 CMD_STATUS=11 的 payload FIFO 等待。
已用正常 FB 关闭/恢复重置主机，恢复有效回读。该试验不构成完整 Command Mode 下 Generic 初始化的验证。
该等待也支持把扩展长包留在 Command Mode 的保守实现。

随后完整厂家表在 Command Mode 下另作 Generic/DCS 对照：
vendor_generic=1 将 B0 以上扩展命令换成 Generic 包，标准 11/29/51/53 保持 DCS；
BA/C7 同样读00，04/0A/54/52与DCS实验相同，未观察到这一包类型变更修复寄存器反馈。
已恢复 vendor_generic=0，保留开关用于复现，不将 Generic 认定为当前正确包类型。

## 万用表测量模式

meter_reset_ms=0：正常复位；1～30000：启用延长的低/高/低三个阶段。
仅针对已识别的 raspberrypi,rp1dsi 主机映射寄存器。

测量时保存 LPCLK_CTRL，写0撤销 HS 时钟请求，等待 PHY_STATUS 的 CLK/D0/D1 Stop 位全部为1；
此时不发送命令，RST 低、高、再低各保持指定时间。最后正常释放复位、发送初始化，再恢复原时钟模式。
初始化错误时也恢复保存的时钟配置并保持复位。

已在设备开启 meter_reset_ms=30000 的后台循环，实际日志确认 CLK/D0/D1 Stop 全部进入，
PHY=15bd，并依次出现 RST 低30000ms、高30000ms。系统欠压标志为0。
该模式不会修改冷启动配置，断电后停止。后台循环每轮90秒保持阶段后会有短暂正常初始化及视频阶段。

预期测量：数据/时钟 LP-11 两线分别对 GND 约1.2V；U6 输出侧 RST 低约0V、高约1.8V。
这些是预期值，实际引脚电压仍需用户测量，控制器 Stop 位不能代替万用表读数。

## 验证及日志

所有改动在设备内核6.18.50+rpt-rpi-2712编译，make退出码0；多次FB启停后的ID及状态回读可重复。
新版时钟及诊断过程中未修改内核模块安装位置或启动配置。
多次动态卸载产生的 DRM interface type ID ret=-28 告警仍有出现，但后续命令和FB均运行；
