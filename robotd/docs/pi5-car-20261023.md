# 2026-10-23 上车部署与音响测试

目标为 `iprpi@192.168.3.109`，Raspberry Pi 5 / Debian ARM64，
内核 `6.18.50+rpt-rpi-2712`。本轮眼屏和MCU未接，不启用底盘或颈部。

## 服务与配置

- 部署仓库 `4158c72` 对应的 `robotd 0.2.0` Linux ARM64发布包。
- 二进制：`/opt/robot/bin/robotd`；依赖检查和真实运行通过。
- 服务：`robotd.service`，用户 `robot`，加入 `dialout` / `audio`，已启动并启用开机运行。
- 数据库：`/var/lib/robotd/robotd.sqlite`，服务端是唯一配置写入入口。
- 监听：`127.0.0.1:50051`；此次通过SSH转发到开发机127.0.0.1:15051测试，没有开放局域网控制端口。
- 最终配置revision=4，音频开启，其余设备关闭；simulated=false、fault为空、stopped=true。
- `screen-monitor.service`和持久journal继续运行；实测throttled=0，EXT5V约5.092V。

## 接口与boot配置

原理图中U2/U3采用旧平台UART名称，Pi 5实测映射为：

| 接口 | GPIO | Pi 5运行端口 |
| --- | --- | --- |
| 板U2：TX/RX/RTS | 0/1/3 | `/dev/ttyAMA1` |
| 板U3：TX/RX/RTS | 4/5/7 | `/dev/ttyAMA2` |
| I2S：BCLK/WS/DOUT | 18/19/21 | `plughw:CARD=sndrpirpidac,DEV=0` |

先运行时加载并核对pinctrl与设备枚举，再备份并追加boot配置：

```ini
[all]
dtoverlay=uart1-pi5,ctsrts
dtoverlay=uart2-pi5,ctsrts
dtoverlay=i2s-dac
```

原配置备份为 `/boot/firmware/config.txt.before-robotd-20261023`。
使用手动RTS，串口自动流控关闭；实测RTS断言true时物理低电平，对应板上低有效发送使能。
`ttyAMA10`调试控制台未修改。本轮没有重启设备，因此boot后自动枚举尚未实测。

## 音响实机通过

通过robotd的PlayAudio RPC输出真实PCM16LE，不是模拟或独立播放器：

1. 48kHz、双声道、2秒440Hz、2%数字峰值，完成96000帧，用户反馈声音不够明显。
2. 48kHz、双声道、2.5秒三声渐高提示音，12%数字峰值（比前次约高15.6dB）。
   完成120000帧，ALSA缓冲40ms，无错误、无插入静音、无重新缓冲。
   用户确认“能清楚听到，正常”。

上述RPC完成时间/后端提交时间不代表麦克风测得的出声延迟。
现场声卡枚举名为snd_rpi_rpi_dac，使用通用被动I2S输出，不读写功放I2C。

## 机械臂按用户要求暂停

用户确认机械臂上电、周围有空间，但线未整理，要求只以当前位置做小幅运动。
本轮没有发送任何位置目标，没有回零或转到1500中位。

- 先使用robotd读取配置中的ID 0/1/2/3，在115200及1000000下均未得到位置反馈。
- 停止robotd独占串口后，检查原始查询和两种RTS电平，原始回包为空；不据此断言硬件损坏。
- 用户随后说明舵机买来未修改参数，怀疑多个舵机ID相同，并明确要求先等等。
- 已停止查询；通过不连接硬件的配置会话关闭双臂，再恢复真实robotd。
  最终left_arm/right_arm.enabled=false，不会继续后台查询或下发动作。

后续先逐个接入舵机确认ID、波特率，分别为每条总线分配唯一地址。
两条总线之间允许相同ID，同一条总线不能重复。
不要在多个未编址舵机同时连接时广播修改ID。
获得每个关节可靠位置反馈后，再记录当前位置并逐关节做小角度、慢速往返。
机械限位、方向和零位尚未标定，默认中心1500及±0.5rad不得当作已验证的机构参数。

本机原始状态/音频结果保存在忽略目录 `screen/bringup/robotd-*.json`。
