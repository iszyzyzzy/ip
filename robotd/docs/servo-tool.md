# 单颗舵机调试工具

在树莓派运行 `robotd/examples/servo_tool.py`。仅依赖 Python 3 和 pyserial；这是独占串口的现场调试工具，使用前停止 robotd，不要同时运行其他串口程序。

```bash
sudo systemctl stop robotd
python3 servo_tool.py --port u2 --id 1
# 或另一侧：python3 servo_tool.py --port u3 --id 1
# 完成并退出工具后恢复服务：
sudo systemctl start robotd
```

`u2` 是 `/dev/ttyAMA1`（GPIO0/1/3），`u3` 是 `/dev/ttyAMA2`（GPIO4/5/7）。默认115200、ID 1。使用低有效发送的内核自动RTS，发送期间低、接收期间高；不再使用实测会影响正常回包的手动切换。

菜单提供查询、改ID、脱力、保存当前位置为上电位置、小幅摆动、保持当前位置。切换总线或选择另一颗舵机时退出后修改 `--port` / `--id` 重开。未知ID时，只接一颗舵机，以 `--id 255` 启动并改号；每条总线分别保证ID唯一。

- **保存上电位置**发送 `PCSD`，不是 `PSCK` 零点校准。先托住臂体、脱力、手动摆到需要的姿态，再选择保存；该命令按厂家资料保存当前位置及当前上电动作/速度。它不主动修改上电动作模式，也不立即命令舵机走到这个位置；保存后需要重新上电验证。
- **小幅摆动**先用 `PRAD` 获取当前位置，确认后以 `PULR` 恢复扭力，再默认上下20位置单位，最大50，每段1秒，最终返回起始读数。每段结束都读回实际位置；全程读数没有明显变化时，会提示并查询工作模式与温度/电压，不把“命令已发送”当成运动成功。位置命令没有ACK是协议允许的表现。不把1500当作机构安全零位；幅度是协议位置单位，未经标定不能视为准确角度。按 Ctrl+C 停止本次轨迹，不自动脱力。
- 改ID及保存操作不自动重试，避免状态不确定时重复写入。厂家旧固件可能不返回成功ACK，脚本会明确提示未确认；改ID会额外查询新地址验证。ID与上电位置是否掉电保存，需重新上电核验。
- 退出工具仅释放串口并将RTS恢复高电平，不主动改变扭力状态。最后一次若执行脱力，退出后仍保持脱力；需要重新保持时选菜单6。

只读检查可使用 `python3 servo_tool.py --port u2 --id 1 status`。诊断错误回包（如 `PTPERROR`）会原样打印。

## 双臂整体往返

`servo_roundtrip.py` 与 `servo_tool.py` 放在同一目录。默认U2、U3每侧ID 1/2/3/4，共8颗；先读取全部起点，任何一颗读不到就不开始。每颗从自身起点增加200位置单位，默认每段3秒，再返回自身起点；近同时逐颗下发，不保证硬件同步。协议范围500～2500只作为数值检查，不代表机构和线缆行程。

```bash
sudo systemctl stop robotd
# 先预览，退出所有已打开串口的单颗调试工具：
python3 ~/robot-bringup/servo_roundtrip.py
# 实际执行，确认8颗舵机均有相应活动空间：
python3 ~/robot-bringup/servo_roundtrip.py --run
# 调整示例：仅一侧、反方向200、每段5秒
python3 ~/robot-bringup/servo_roundtrip.py --ports u2 --offset -200 --duration 5000 --run
sudo systemctl start robotd
```

两段分别回读实际位置，任一差值超过10时报告未跟随。运行前不发送脱力、重新校准或恢复扭力命令。Ctrl+C或读取失败时尝试停止全部轨迹，保留扭力，不自动回程；不循环运动。所有运动默认使用各自读回的起点，不前往1500。
